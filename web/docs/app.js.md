# `static/app.js`：前端流程控制

`state` 保存当前 `designId`、`runId`、目标模式、候选页码、轮次，以及 `designReady`、`hasExperiment`、`feedbackComplete` 等进度标记；`updateProgress` 据此刷新左侧流程栏与卡片编号的完成/当前状态；`watchSections` 用 `IntersectionObserver` 给当前可见卡片对应的流程项加 `viewing`，点击流程项即滚动到对应卡片。`setMode` 切换单/多目标并按 `state.objectives`（多目标时 2–4 个，由 `#objective-count` 经 `setObjectiveCount` 设置）显示目标行，再刷新 `updateTargetSummary`；`targets`/`directions` 按 `objectiveCount()` 读取前 N 个目标槽位 `TARGET_SLOTS`；`checkTargets` 在下载模板和上传实验前校验目标列名（非空、英文字母开头、只含字母数字下划线、互不重名），逐条指出第几个目标有问题；两个模板按钮经 `templateButton` → `downloadTemplate` 用 `fetch` 取回 CSV 再触发下载，接口报错时在「实验数据」卡片显示原因，页面不会跳转到错误 JSON；`uploadExperiment` 先由 `readExperimentFile` 在浏览器端拦截 Excel 文件、非 CSV 扩展名、空文件、超过 20 MB 和空目标列名，再把两种模板填写后的 CSV 提交到配方导入接口并刷新候选池；`showExperimentResult` 在「实验数据」卡片内以成功/警告/失败样式显示标题和逐条说明，`uploadFailed` 把接口返回的 `message` 与 `details`（逐行问题）列在上传按钮下方，`afterExperimentImport` 在目标值完整的实验不少于 2 条时跳转到「模型优化」；`setExperimentLocked` 在设计已有运行时禁用上传；`additiveRow` 管理可选添加剂行；`updateNextRound` 根据运行的 `feedback` 状态说明为什么可以或不能生成下一轮；`syncHyperparameters` 根据核函数与目标数量启用或隐藏超参数输入（噪声与参考点各 4 个槽位，只显示前 N 个）并按目标名标注，`hyperparameters` 组装启动运行时的超参数，`applyHyperparameters` 在切换到已有运行的设计时回填其设置（「恢复默认」使用 `HP_DEFAULTS`）；`loadAcquisitions` 启动时读取 `/api/v1/acquisitions`，`syncAcquisition`（由 `syncHyperparameters` 调用）在单/多目标切换时重建 `#hp-acquisition` 选项（已有运行的选择经 `dataset.pending` 恢复，否则取模式默认值），显示所选预设的说明，并只显示其 `params` 对应的输入框（`hp-<参数名>-field`），`acquisitionText` 把采集函数及参数加入运行摘要；启动失败的原因写在按钮旁；`renderRunSummary` 在「模型优化」卡片显示本轮模型的训练规模（来自 `training_summary.json`）及实际使用的超参数（`hyperparameterText`）和随回传实时变化的下一步（待回传数量或累计已测数）。`selectDesign` 切换设计时清空上一设计的运行状态与推荐表。「当前设计」下拉框只列出本次打开页面后生成或载入的设计（`sessionDesigns`，刷新即清空）；服务器上的设计目录仍保留，只是不再自动出现在列表中。`call`/`post` 是统一 API 请求入口；`configFromForm` 把配方表单转换为步骤 1 的 JSON；`createDesign`、`loadCandidates`、`uploadExperiment` 处理候选和初始实验；`startRun`、`pollRun`、`loadRecommendation` 负责异步运行及产物预览；`submitFeedback`、`simulate`、`nextRound` 处理连续轮次。

前端可编辑推荐性能值，提交时按 `sample_id` 和目标列名构造 `measurements`；也能上传填好的推荐 CSV。回传成功后刷新推荐和可视化。`recipeTable` 把 `compound_i`/`mass_ratio_i` 合并成“组分 + 质量百分数”的组成列（只列非零组分，调用 `visualization.js` 的 `compositionHtml`），推荐表额外显示目标列，完整列仍在下载 CSV 中；catalog 含 `salt_molality_mol_kg` 时另加一列“锂盐浓度 mol/kg”。步骤 1 的锂盐行由 `saltRow` 生成（最多 `MAX_SALTS` = 12 行，`syncSaltRows` 在只剩一行时隐藏删除按钮、满 12 行时隐藏“＋ 添加锂盐”），`configFromForm` 输出 `salts` 列表。锂盐、添加剂上下限变化后，`updateSaltMolality` 去抖调用 `/api/v1/salt-molality-range`，在 `#salt-molality` 显示换算的 mol/kg 区间。表格内容通过 `escapeHtml` 处理后插入页面。

迁服务器时，首先把 `api='/api/v1'` 变成构建环境配置；其次考虑任务断线重连、身份认证与权限、长耗时任务状态展示。不要只在浏览器内保存 run ID；当前后端目录已能列出设计与运行，后期应使用用户/项目关联。


第一步新增 `saltSpaceSizes`、`updateSaltSpacePreview` 和 `fillFiveSaltExample`：选择单盐／双盐模式、实时预览组合数及总预算分配、填入五盐三溶剂示例。`configFromForm` 增加 `salt_selection.sizes` 与 `sampling.require_all_solvents`。生成后 `renderSamplingSummary` 从设计状态中的 `counts.salt_spaces` 渲染各固定组合的撒点数、保留数和零覆盖提示；这些统计对应初次生成，后续导入不会改写。其余 BO 表格、模型、采集函数与回传流程沿用原实现。
