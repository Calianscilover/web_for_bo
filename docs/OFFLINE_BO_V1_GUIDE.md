# 离线策略比较 V1 使用说明

入口：[本机 8766 离线页面](http://127.0.0.1:8766/offline)。在线首页顶部也提供入口。服务启动方式沿用 `bayesian_optimization/run.py`，不需要额外服务或安装依赖。

## 使用步骤

1. 载入「CRR 示例 · 41 条」、上传实验 CSV，或读取已有设计的实验数据。
2. 核对上传后的表格识别结果，再选择配方格式：A 是在线模块下载的实验模板，含 `experiment_id + <组分>_mass_g`（或 `_mass_fraction`）和性质列；B 是 `compound_i + smiles_i + mass_ratio_i / mole_ratio_i / ratio_i` 候选或模拟推理目录。混合表不会隐式优先读取旧槽位。`ratio_i` 没有单位信息，须在下拉框明确选择 UniELF 摩尔分数或完整组分质量分数。
3. 默认选择「仅组分数据 · 从文件读取」，点击「校验配方信息」即可；不要求预登记身份库，也不要求指定盐／溶剂角色。确实需要检查实验空间时，切换「按配方设计校验」，再选择已有设计或输入设计 JSON，检查盐数、溶剂必含和比例范围等。额外的 `salt_molality_bounds: [下限, 上限]` 按 mol/kg 溶剂检查，不解释为 mol/L。
4. 配方通过后，选择 `CRR[%]`、最大化、目标来源及单位，点击「校验目标性质」。原目标列名保持显示，运行内部采用统一别名 `offline_target`。不自动把百分数除以 100。
5. 点击「冻结数据集」。目标缺失时，必须先修正，或明确勾选排除缺失配方后重新校验。默认不随机填充目标。
6. 设置共同初始数、总预算（含初始）、每轮数和重复次数，选择策略并开始。快速试运行固定 5 次重复，保留当前预算；正式比较使用页面设置的重复次数。
7. 在「进程与可视化」查看运行状态和双图：左图为优化轮次与截至该轮已发现的最佳目标值；右图为累计实验预算与数据集最优配方发现率。方法汇总、结果下载及单次查询轨迹折叠显示。页面 URL 带 benchmark ID，刷新后可以恢复查看。

左图第 0 轮表示初始化，一轮批量推荐记一轮（尾批也记一轮）；只汇总已完成重复的实际最佳值，实线／虚线区分方法，中位数配 IQR 阴影。最大化画最大值，最小化自动画最小值，灰色水平线为冻结数据集最优值。尚未完成的重复不会提前贡献未来轮次。右图保留以计划重复次数为分母的发现率，累计预算包含初始与完整批次，可反映方法在相同实验成本下找到最优配方的稳定性。

## 实验模板与模拟数据导入（本次迭代）

默认的仅组分模式由 `offline_benchmark/composition.py` 直接从文件建立特征，完全不查询预设身份库。质量模板的数值校验仍复用在线模块的 `recipe_composition`。按设计模式沿用 `pool_row` 与 `transform_rows` 的完整盐转换规则。离线数据始终写入独立目录，不修改原在线设计的池或实验。

- B 表按规范 SMILES 建立整张表的组分集合，槽位顺序变化不改变组分含义；同一结构的不同名称归为同一组分，不同行未使用的位置补 0。同一名称对应不同 SMILES 会报错，避免把两个物质混作同一特征。
- 默认保留文件中的分子／离子表示，例如 `1846` 和 `1954` 分别作为 PF6−、Li+ 的原始组分，不强制配对为完整盐，也不推断盐／溶剂角色。`mole_ratio_i` 与显式选择摩尔基准的 `ratio_i` 都可直接使用。SMILES 有效时按分子量换算另一套比例，原表两套比例同时存在时进行交叉校验。
- A 表只有名称与质量也可使用任意新组分，不猜测其化学结构；仅生成质量分数特征，页面禁用摩尔分数，接口也拒绝不具备的基准。若需要摩尔特征，可在可选 JSON 中提供 `components: [{"name": "组分名称", "smiles": "..."}]`，无需提供角色。不会用假 SMILES 或假分子量填补。

- `EXAMPLE` 开头的实验编号和全空行跳过；空白实验编号按 CSV 原始行号追溯。空白组分按 0，总称量质量不限。目标缺失在第二部分处理，不在配方校验时假装已有测量值。
- 配方校验后可展开组分及前五条质量分数预览，下载可用基准的标准配方目录、原始行号／编号映射及报告。转换目录不携带任何性质值。
- 默认模式按结构或名称的稳定顺序生成独立的组分特征编号，原始编号保存在映射中。它与按设计模式属于不同表示，不混用两种模式的运行结果；绑定同一设计的按设计模式仍与在线导入编号一致。
- 按设计模式才使用已知身份／角色库，才检查单／双盐、溶剂必含、比例范围及已知 1:1 锂盐的离子配平与还原；此模式中自定义物质需提供身份和角色。仅组分模式不会执行这些化学约束，但仍检查比例为有限非负数、总和、非零空槽位、重复来源 ID 冲突及温度一致性。
- 推理结果中的原始性质和 `*_pred` 均可选择；`*_pred_std / *_model_devi` 为辅助信息，不进入配方和目标选项。选 `*_pred` 时来源设为外部模拟／计算值。不会用预测值自动填补原始性质的空缺。

用户提供的实验文件核对结果：22 行中有 2 行 EXAMPLE，正式配方 20 条，组分 LiDFOB / NDFA / TTE，Conductivity 范围 0.91–1.89；默认模式可直接进行质量特征优化。推理文件核对结果：52 条配方，默认模式保留 9 个原始分子／离子组分；按设计模式可还原为 8 个完整盐／溶剂组分。`CRR[%]` 与 `CRR[%]_pred` 独立选择，后者有 52 条已填值。原文件均不修改。

新增端到端测试实际生成在线候选池、调用两个模板下载接口，在自有模板下追加 20 条正式实验，分别导入在线和离线模块，验证两端的 sample_id 集合完全相同；同时检查拆分离子重建的质量分数、比例基准确认、预测列来源及不平衡拒绝。

`inference_result (2).csv` 兼容性核对：原文件 128 行、温度统一为 0 °C；默认组分模式直接读入 6 个组分（含 PF6− 与 Li+），得到 26 个唯一配方，重复记录按所选目标取均值。无需手动调整溶剂必含。若使用按设计模式，则可还原为 LiPF6 与四个溶剂共 5 个组分，并需允许溶剂组合变化。原始性质与预测列各有 128 条非空记录，原文件不修改。

## CRR 示例与验证结果

仓库示例 [web/examples/crr_example.csv](../web/examples/crr_example.csv) 从用户指定的 `pool_catalog_crr_preprocessed.csv` 提取八种明确的参考质量列、CRR 及必要来源信息，共 41 个唯一配方；没有复制 Raman 路径或有歧义的离子槽位。原文件不修改。

示例包含 LiDFOB、LiPF6、LiFSI、LiBF4、LiTFSI、TTE、FEC、DME。按设计的基础规则下，全体均满足 1–2 种盐和全部三种溶剂必含；目标范围为 14.93–85.44。质量列由原数据声明为参考质量，不能称为原始称量记录。仅组分模式将其视为名称与质量特征，不额外推断分子量。

完整原文件也可直接上传：它会识别出两种可能的格式，用户应明确选择 A 路径，按质量列重建固定特征；旧的 `compound_i` 槽位不会参与该路径。若选择 B，需先解决槽位及化学身份问题。

用户原文件内的 `constraint_current_design_pass` 有 6 条 False。V1 不采信这些旧标记直接筛选：是否保留由用户绑定的设计及本次实际校验决定。不要把“默认基础规则下 41 条通过”解释成“41 条全部满足原先的浓度和比例限制”。

页面验证已完成一组小规模回放：6 个策略 × 2 次重复，初始 8 条、总预算 12 条、每轮 1 条，12 个子任务均完成。它是流程验证，不是判断哪种采集策略最优的统计结论。正式研究可从 20 次配对重复、预算 24 开始，再检查分布和敏感性。

## 回放与可追溯性

- 所有方法在同一次重复中共享同一初始集合。不同重复用独立、可重现的种子派生。
- GP 和采集函数复用 `algorithms/bo_utils.py`、`algorithms/acquisitions.py`；Random 无模型。
- 每轮推荐 CSV 先留空目标，查冻结目标表得到值，再调用在线与离线共用的 `apply_feedback` 做完整批次校验。在线的真实／随机模拟接口保持原入口。
- 候选 catalog 不含目标列；每次训练只读取已揭示的 observation。每轮 `training_audit_*.json` 记录训练 ID 和特征列，`experiment.csv` 始终只包含初始样本。
- 第 0 轮代表初始化；批量命中计整批成本，尾批按剩余预算缩小。未命中不填成虚假发现轮次，失败单独报告。
- 取消在轮次边界生效。停止／失败后可恢复，已完成的子任务不重跑；已提交推荐先核对冻结真值，轨迹重建而不重复计费。
- 数据目录为 `bo_test/offline/datasets/`，比较目录为 `bo_test/offline/benchmarks/`。不要手动修改冻结数据或运行目录再接着回放。

## 当前范围

V1 是单目标、固定已知性质池、均匀无放回初始化。包含 6 种既有单目标采集函数和 Random；默认选中 5 种寻优函数及 Random，纯探索 `qstd` 可选。

默认模式只要求组分数据，支持质量模板中的未登记名称和模拟目录中的任意有效 SMILES。按设计模式另有盐种数、必含溶剂、质量／溶剂池分数、温度及显式 molality 范围校验；没有从估算 molarity 列自动推断 mol/L 约束，也没有验证溶解度。

暂未加入分层初始化、配对 bootstrap 区间、多目标评测和自动选出“普遍最好算法”。曲线阴影是 IQR，不是置信区间。恢复后的耗时包含已记录的前次耗时；强制终止时未写入的那段耗时无法精确恢复。

## 验证命令

在装有项目依赖的解释器中运行：

```bash
cd web
python -B -m unittest test_offline test_integration
```

测试覆盖两阶段闸门、CRR 原名与别名、A/B 等价表示、错误槽位、缺失目标、冻结文件变更、全部 7 个策略的真值回放、训练标签隔离、尾批预算、恢复、最小化、条件及浓度校验，以及原在线多轮流程。

前端图表语义检查：在项目根目录运行 `node web/test_offline_charts.cjs`，覆盖轮次与尾批、完成重复的汇总、最小化、零／负值、空状态与发现率口径。
